# Backend dependency audit triage — 24/11/2026

`npm audit` against `backend/package-lock.json` (SHA256 `C2E84E0532BE59DE94A72891201AE9AF173C20237C8175CBEF0472DA52BA72F1`) reports 30 advisories in the full tree (7 high, 23 moderate). `npm audit --omit=dev` reports 13 dependency-tree entries (4 high, 9 moderate). The latter is **not** an inventory of the pruned production image: npm includes Prisma CLI through an optional peer edge from `@prisma/client`. A read-only `npm ls` inside the currently running `lambe_server` image showed `prisma` and `@prisma/config` absent, but the nine moderate transitive packages listed below present. The image may predate these source edits; rebuild verification remains open.

| Dependency group | Observed path and reachability | Decision |
| --- | --- | --- |
| `prisma`, `@prisma/config`, `deepmerge-ts`, `effect` (4 high entries) | Prisma CLI/config is used at build/migration time. The current production image omits the CLI/config after `npm pkg delete devDependencies` and `npm prune --omit=dev --omit=peer`. The [deepmerge-ts advisory](https://github.com/advisories/GHSA-ggr8-5vv4-36mx) requires recursive object graphs; plain JSON does not trigger it. The [Effect advisory](https://github.com/advisories/GHSA-7589-6fvf-x4pw) requires a vulnerable template-literal schema and untrusted input. No backend HTTP path to these CLI dependencies was found. | Defer Prisma major upgrade to a separate compatibility/migration plan; do not force an untested major change into the performance work. Recheck the rebuilt image and CI/build input trust before accepting risk. |
| `@nestjs/swagger` → `js-yaml` | The current image contains `js-yaml`. Swagger document generation is gated to development in `configure-app.ts`; no backend endpoint parsing client-supplied YAML was found. The [advisory](https://github.com/advisories/GHSA-r3ph-w7gj-g6xm) concerns YAML merge processing. | Update within the compatible Swagger dependency range in a separate small dependency PR, then rerun API contract tests and audit. |
| `firebase-admin` → Google libraries (`google-gax`, `gaxios`, `gcp-metadata`, `rimraf`, `glob`, `minimatch`, `uuid`) | These packages are present in the current image. Firebase auth/messaging can run in production, so this is a real runtime dependency chain. The `uuid` advisory specifically concerns caller-supplied output buffers in v3/v5/v6; no Lambe call using that API was found. The glob/rimraf advisories concern filesystem pattern handling; no request-controlled pattern path was found in Lambe. This is a source-path inference, not exploit validation. | Treat as reachable runtime supply chain and prioritize compatible transitive updates in a separate PR. Validate Firebase token verification and push delivery, then re-audit the rebuilt image. Do not mark the nine moderate entries resolved yet. |

The `npm audit fix --dry-run` preview proposes broad dependency churn, including test/build packages, so it was not applied to this mixed worktree. No advisory was suppressed and no major dependency upgrade was made. The next decision gate is a small isolated dependency PR with exact version diff, full `npm run check`, Firebase integration verification, `npm audit` and image-level `npm ls` evidence. Runtime exploitability remains unproven; this triage only narrows which paths require that verification.
